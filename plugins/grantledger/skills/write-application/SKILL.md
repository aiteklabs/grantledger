# Write an application

The user wants a first draft they can edit and submit themselves. You write from two sources only: what the call asks for, and what the user confirmed or tells you. Nothing is sent to GrantLedger: the tools are read only.

## Steps

1. Identify the call and the profile. Call `my_profiles`, then `get_fit` for the profile, then `get_grant` for the call. If the account has no saved profile, ask for a grantledger.eu/fit/<id> link or point to https://grantledger.eu/find
2. Check the verdict. If the screening says `no` or `not_yet` for this call, say so first with the rule it relies on, and name the alternatives from the memo. Verdicts come from fixed rules on grantledger.eu; do not overrule them. Write only if the user still wants it.
3. Read what the call asks for. The application form, the template and the evaluation criteria are on the official publisher page (`source_url`) or in the files under `documents`. Open them with your web or file tools. If you cannot open them, ask the user to paste or upload the form or the template.
4. Show the outline before writing: every section the form asks for, in its order, with its length limit and the criterion it answers. Ask the user to confirm it.
5. Ask for the facts you need and do not have, in one short list: the project, its budget, the partners, the results so far, the numbers that prove each claim. The profile gives the organisation (type, size, age, country, sector), not the project.
6. Write one section at a time, in the order of the form. After each one, list what the user must check or supply.
7. When the draft is complete, offer to score it against the call's criteria.

## Rules

1. Never invent a fact about the user, the project, a partner, a budget line or a result. Where a fact is missing, write a placeholder in square brackets that names what is needed, for example [turnover 2025, from the annual accounts].
2. Never invent a requirement of the call. Follow the form and the criteria as published; quote the source when you rely on one.
3. Write in the language the funder requires. If the call does not say, use the language of the call and tell the user.
4. Respect every stated limit: characters, words, pages, budget ceilings, funding rate. Say the length of each section you write.
5. Write for the evaluator: answer each criterion in the terms the call uses, state the claim first, then the evidence. No filler and no superlatives without a number behind them.
6. Amounts, deadlines and currency exactly as in the record. Say clearly when the call is closed or the deadline has passed.
7. Tell the user to read the funder's rules on the use of AI tools in applications; some funders ask applicants to declare it.
8. The user submits themselves on the official publisher page. You cannot submit anything, and a draft is not a guarantee of funding.
